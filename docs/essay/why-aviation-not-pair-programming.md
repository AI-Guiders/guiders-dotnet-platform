# Почему кокпит, а не Pair Programming

**Status:** published (2026-08-25)  
**Tags:** #aviation #human-factors #agent #pair-programming #cockpit #essay  
**Related:** [GUIDERS-ADR-0007](../adr/GUIDERS-ADR-0007-aviation-mental-model.md) · GUIDERS-ADR-0006 · GUIDERS-UI-0004

---

Когда мы говорим про human + AI в IDE, почти неизбежно слышим:

> «Ну это же просто Pair Programming. Зачем авиация?»

Вопрос честный. И если ответить небрежно — «так красивее» — он заслуженно отправит всю метафору в корзину. Ниже — зачем мы **не** называем это pair programming и **почему** borrowed language из авиации здесь уместнее, чем из классического software engineering.

---

## 1. Что на самом деле решает Pair Programming

Pair Programming (и Mob Programming как его старший брат) — про **социальную координацию людей** вокруг одной задачи:

- два (или больше) **людей** сопоставимой роли;
- **одна клавиатура**, общий экран, общая «комната»;
- **общая краткосрочная память** сессии — оба были здесь с первой минуты;
- договорённости: driver / navigator, смена ролей, коллективная ответственность за код.

XP вокруг этого даёт ритм: TDD, малые шаги, рефакторинг, обратная связь. Это сильный остров SE — **как люди вместе пишут софт**.

Но он почти ничего не говорит о другом вопросе:

> **Куда смотреть, когда каналов информации больше, чем пропускная способность внимания — а второй участник не человек?**

---

## 2. Human + Agent — не пара

Сравнение «AI = второй разработчик в паре» удобно для маркетинга и вводит в заблуждение.

| Pair Programming | Human + Agent (реальность) |
|------------------|----------------------------|
| Симметрия | **Асимметрия**: память, скорость, инструменты, ставки |
| Один контур внимания | Editor, MCP, KB, CI, Usage, diff, чаты |
| Оба в одной сессии | **New Chat = новая ипостась**; continuity через KB, не через голову |
| Социальный контракт | Протоколы, briefing, symbology, tools |
| «Вместе думаем» | Один держит маршрут, другой может «пролететь» 8M токенов за ход |

Назвать это pair — значит **схлопнуть** проблему до знакомого ярлыка. Проблема другая: **асимметричный экипаж** при **множестве приборов**, а не нехватка людей у клавиатуры.

Мы не против парной работы. Многие сессии *ощущаются* как «вместе в одном leaf» — и это хорошо. Но **приборная модель** для этого не подходит так же, как **кокпит** не подходит для описания stand-up meeting.

---

## 3. Почему «AI Pair Programmer» — тупиковая метафора

Вендоры любят «ваш AI-партнёр по программированию». Оператор быстро обнаруживает:

- партнёр **не помнит** вчерашний чат, если не поднять KB;
- партнёр может **молча** сжечь пул Cursor Models за один длинный ход;
- партнёр **не равен** по ответственности: invoice на человеке, не на модели;
- партнёр иногда **уверенно врёт** — в паре с человеком это CRM-проблема, не «надо чаще меняться местами».

Pair programming предполагает **взаимную корректируемость** и **общую ситуационную осведомлённость**. У агента situational awareness собирается из **briefing** (Correspondence), не из «мы же в одной паре».

Отсюда и усталость от островов OSS: каждый README кричит «easy integrate», но никто не описывает **контур внимания** между human и agent. Авиация этим занимается десятилетиями — не потому что пишем софт для Boeing, а потому что **human factors** там первоклассный.

## 4. Что даёт авиация (и чего нет в XP)

Авиация — не «домен предметной области». Это **язык дефицита внимания** при высоких ставках.

| Авиационная идея | Проблема в habitat |
|------------------|------------------|
| **PFD** — главное сейчас | Редактор / текущий leaf, не свалка всего |
| **MFD** — по запросу | Docs, wire graph, peek в ADR |
| **EICAS** — W/C/A, Dark Cockpit | Drift и тревоги **только** когда рассогласование; в норме тишина |
| **CDS** — маршрутизация внимания | Что на каком «стекле»; не один бесконечный лог |
| **Symbology** — стандарт знаков | ASP: agent и human читают одну семантику разными профилями |
| **Briefing / FMS** — картина до действия | Correspondence: «вот что известно — посмотри» |
| **Checklist** — смена фазы | Опционально на **код**, не на написание flight manual |
| **CRM** — экипаж + automation | Оператор + агент: speak up, границы, не симуляция равенства |

Ни Mob, ни Pair не дают:

- иерархии предупреждений;
- различия **briefing** vs **checklist**;
- **Dark Cockpit** как нормы;
- **symbology layer** для machine + human exposure.

Это не украшение. Это **сжатый словарь** для проблемы, которую SE-острова называют иначе или не называют вовсе.

---

## 5. Что мы всё равно берём из XP / Mob

Контуры **не враги**:

| Из XP / Mob | У нас |
|-------------|--------|
| Короткие итерации | ADR slices, green journey tests |
| «Вместе в задаче» | Один leaf, один ship за сессию |
| Обратная связь | CI, conformance, EICAS на drift |
| Не тащить лишнее | Federation: не аннексировать чужие острова |

**Процесс** — mob/pair дух. **Когнитивная архитектура** — кокпит. Одно не заменяет другое.

---

## 6. Одна фраза для скептика

> **Это не Pair Programming. Это Crew Resource Management для асимметричного кокпита, где второй пилот не человек, а приборов — слишком много.**

Или мягче:

> Pair — про двух людей у одного стола. У нас стол один, но экипаж асимметричный — для этого у aviation есть язык, у XP его нет.

## 7. Как это легло в платформу (не обязательно читать)

Мы зафиксировали это в [GUIDERS-ADR-0007](../adr/GUIDERS-ADR-0007-aviation-mental-model.md):

- **Phases** 0–5 (certification → symbology → route → CDS → surface → FDR);
- **UI contour** (ASP, symbology) и **canon contour** (Correspondence, briefing);
- **Checklist** только Dev profile на код; **не** gate на ADR/KB;
- agent-native, IDE-agnostic: Cursor, CIDE, opencode — разные стёкла, один CDS contract.

Confederation ([GUIDERS-ADR-0006](../adr/GUIDERS-ADR-0006-confederation-charter.md)) — **маршруты между планетами**. Авиация — **как не убить экипаж по дороге**.

---

## 8. Зачем писать это публично

Потому что вопрос «зачем авиация» — не про любопытство. Это **тест на зрелость метафоры**. Если мы ответим «ну так круто» — нас правильно проигнорируют. Если ответим честно — **pair решает другое, кокпит решает перегрузку при асимметрии** — метафора становится инструментом, а не лозунгом.

Мы не просим всех IDE рисовать бортовые панели. Мы просим признать: **human + agent — новый класс экипажа**, и у него уже есть учебники — просто они лежали в другом ангаре.
